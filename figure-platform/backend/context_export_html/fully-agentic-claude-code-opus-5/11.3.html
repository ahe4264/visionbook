Collision resolution by chaining

Every key k of the universe U is sent by the hash function to slot h(k) of table T; all keys landing in one slot are held in a single doubly linked list. Edit h below and watch the chains re-form — h alone decides how the actual keys K are partitioned and how long the chains get.

Reading the picture: a shaded slot crossed by a diagonal slash is NIL (empty chain); a white slot stores a pointer to the head of its list. Each list node has three cells — previous pointer, key, next pointer — and a diagonal slash marks a NIL pointer. Insertion happens at the head of the list (CLRS CHAINED-HASH-INSERT), so a chain reads in reverse insertion order. Hover a key, a slot or a node to trace one key across the whole mapping.
